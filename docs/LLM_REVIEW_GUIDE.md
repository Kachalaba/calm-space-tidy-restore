# Calm Space — guide for external LLM review

## What to share

Preferred source: the public GitHub repository linked from the project
`README.md`:

`https://github.com/Kachalaba/calm-space-tidy-restore`

For an LLM with local workspace access, provide the repository root (`./`) as
the complete Unity project.

Do not point a reviewer at `Library`, `Logs`, `Builds`, `UserSettings`, or
`.utmp`. They are generated locally and are intentionally excluded from Git.

## Product intent

Calm Space is a portrait Android hybrid-casual antistress game. A session
should feel tactile, forgiving, and quietly satisfying: arrange objects, sort
compatible shapes, restore small spaces, and clean a surface with soft ASMR
audio and Android/iOS haptics. There are no timers, penalties, fail states, or
forced ads in the demo.

The repository is a polished vertical slice for device testing and design
evaluation, not a finished commercial release. Real ad, billing, consent, and
production-signing providers are deliberately not included.

## Open and reproduce

1. Use Unity `6000.0.80f1` or a compatible Unity 6 editor.
2. Open the project root, then
   `Assets/CalmSpace/Scenes/Main.unity`.
3. Run `Calm Space > Configure Project` after changing authoring builders.
4. Press Play for desktop interaction, or build the Android development APK
   from `Calm Space > Development > Build Android Test APK`.
5. Run both EditMode and PlayMode tests from Unity Test Runner.

The project uses a single persistent scene. Eight gameplay prefabs are
loaded through Addressables.

The verified baseline is 118 passing EditMode tests and 35 passing PlayMode
tests. The Android development build is ARM64/IL2CPP with API 24 minimum and
target API 36.

## Important authoring rule

`Main.unity`, the eight level prefabs, level definitions, theme catalog, and
several materials are regenerated by the editor setup pipeline. A proposed
change to generated content must normally be made in the matching editor
builder first, followed by `Configure Project`. Editing only the generated
scene or prefab will not survive regeneration.

## Useful review questions

Ask reviewers to separate four kinds of feedback:

1. **Game design:** Is the 5–8 minute loop varied enough while remaining
   antistress? Which mechanic should become the first deeper content pillar?
2. **Mobile UX:** Are targets, copy, safe areas, navigation, and feedback clear
   at 1080×2400 portrait resolution?
3. **Unity architecture:** Are lifecycle, cancellation, Addressables, DI,
   occupancy, haptics, and zero-allocation interaction paths robust?
4. **Release readiness:** What still blocks Internal Testing, Closed Testing,
   and a public Google Play launch?

For actionable feedback, ask for severity, exact file and line, reproduction
steps, player impact, and the smallest safe fix. Reviewers should not treat the
no-op ad/IAP adapters or development signing as accidental defects; they are
explicit pre-release boundaries.
